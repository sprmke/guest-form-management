## Parking E2E (broadcast booking flow)

Standalone parking bookings now run a complete parking-only lifecycle, separate from the property booking workflow.

| Concern                        | Detail                                                                                                                                                                                                                                                                               |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Status workflow**            | Parking uses its own graph in `.cursor/rules/parking-workflow.mdc`: `PENDING_HOST_ACCEPTANCE → PENDING_REVIEW                                                                                                                                                                        | NO_HOST_AVAILABLE | CANCELLED`, then `PENDING_REVIEW → READY_FOR_CHECKIN → COMPLETED`(with`CANCELLED`allowed where documented). Property`workflowOrchestrator` is not involved. |
| **Candidate matching**         | Guest submit checks org-scoped `ACTIVE` parkings, filters by `accepted_vehicle_types`, and excludes date-overlapping non-terminal parking bookings. Vehicle fit tiers (`compact` / `sedan` / `suv` / `van`) are derived from parking dimensions via `resolveVehicleFit`, not stored. |
| **Guest submit + status**      | Public routes: `/parkings/:parkingSlug/form` submits through `submit-parking-booking-request`; success redirects to `/parkings/requests/:bookingId`, which polls `get-parking-booking-status` every 4 seconds and shows countdown, claimed slot, and optional endorsement note.      |
| **Host notifications + claim** | Each eligible parking host gets Telegram + per-recipient email. First Accept wins through `claim-parking-booking`; declines go through `decline-parking-booking`; TTL expiry is handled by `expire-parking-broadcasts`.                                                              |
| **Data model**                 | See `docs/architecture/data-model.md` for `parkings.accepted_vehicle_types`, `guest_submissions.parking_request_organization_id`, `requested_vehicle_type`, `parking_broadcast_expires_at`, `parking_claimed_at`, `parking_endorsement_note`, and `parking_booking_broadcasts`.      |
| **Route guides**               | Public parking browse + request flow: `docs/guides/routes/parkings.md`. Host dashboard flow: `docs/guides/routes/org/parking/bookings.md`. Full implementation plan/history: `docs/workflow/done/parking-e2e-phase1-overview.md`.                                                    |
| **Playwright coverage**        | Feature-scoped parking E2E lives under `ui/e2e/features/parking/`: mocked guest/host/side-by-side specs plus a local Supabase-backed acceptance path under `live/`. Repo runner config is `playwright.config.ts`; usage guide: `docs/guides/testing/parking-playwright.md`.          |

Property-scoped spreadsheet import wizard — upload host booking history into `guest_submissions` without triggering live booking side effects.

| Concern            | Detail                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| **Storage**        | Private bucket **`import-uploads`** — CSV / Excel (`.csv`, `.xlsx`, `.xls`), 15 MB cap; path `{orgId}/{batchId}/{filename}`. First worksheet only for Excel.                                                                                                                                                                                                                                                                                                                                                                                                                |
| **Booking status** | **`import-commit`** sets **`IMPORTED`** when check-in is **before today (Asia/Manila)**; **today/future** → **`PENDING_REVIEW`** with **`imported_from_batch_id`** (direct insert, not `workflowOrchestrator`). Past **`IMPORTED`** rows excluded from action-required stage cards, SD-refund cron, and guest calendar availability; future import rows behave as normal **`PENDING_REVIEW`**. **Imported** status filter (explicit chip) also matches batch-linked rows via `expand_imported_batch`. |

| **UI**             | **Import** button on property bookings list → four-step `ImportWizardModal` (Upload → Match → Preview → Import). Match keeps automatic and manual review together in clickable **Matched** / **Need input** summary cards, auto-selecting Need input when action is required. Preview has status filters, an error queue, and an in-app fix sheet (`fieldValues` on `import-update-row`); skipped rows reopen the same sheet with **Restore** / **Fix**, walking the skipped queue instead of the error queue. Validation errors include `value` for the failing cell.      |
| **Route guides**   | [`docs/guides/routes/org/property/bookings.md`](guides/routes/org/property/bookings.md).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |

## Host pricing tiers (catalog + entitlements)

**Org-level subscription catalog** (Free → Managed + a retired commission plan) — one `org_subscriptions` row per org, priced **per enrolled property** (tier's per-property rate × property count, volume-discounted) with no property-count cap. There is no per-property subscription: `resolvePropertyEntitlements(propertyId)` resolves entirely through the property's org, falling back to Free when a property isn't enrolled. Plans: [`host-plans-and-pricing-tiers.md`](workflow/done/host-plans-and-pricing-tiers.md) (original per-property foundation, historical), [`org-level-billing-migration.md`](workflow/done/org-level-billing-migration.md) (current model — source of truth), [`pricing-portfolio-bundling.md`](workflow/done/pricing-portfolio-bundling.md) (superseded flat-cap bundle add-on, historical). The feature-gating audit that swept every module against this catalog, hardened server-side enforcement, added the tier-badge system, redesigned the upgrade modal with proration, and added org-wide pooling for quantity-limited features: [`tier-feature-alignment-audit.md`](workflow/done/tier-feature-alignment-audit.md) — canonical feature × tier matrix + gate inventory in [`plans-feature-matrix.md`](architecture/plans-feature-matrix.md).
