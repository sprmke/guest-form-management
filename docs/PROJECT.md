**Admin status colors:** booking status badges, attention chips, resource/import/finance labels, and org dashboard chart fills share one palette in `ui/src/lib/status-tone-colors.ts` (`STATUS_TONE_HEX` — Tailwind 500 hex matching badge dots; `CHART_INCOME_COLOR` / `CHART_EXPENSE_COLOR` in `chartStyles.ts` derive from green/red tones). Primary pill component: `ui/src/features/dashboard/bookings/components/StatusBadge.tsx`.

**Billing is org-level only** — see [`docs/workflow/done/org-level-billing-migration.md`](workflow/done/org-level-billing-migration.md). There is no per-property subscription. Hosts manage the same Plans & Billing UI at **`/org/:orgSlug/plans`** and **`/org/:orgSlug/property/:propertySlug/plans`** (property nav stays in property context; **Continue to payment** hands off to the org route for PayMongo). Details in **Host pricing tiers** below.

**Sensitive settings (payment v1):** Property and parking **Payment** saves require org-owner email OTP before the server accepts payment-field PATCHes. Flow: UI opens verification modal → host taps **Send OTP** → `POST settings-verification` (`send_otp` → `verify_otp`) → PATCH `app-settings` / `parking-settings` with `settingsVerificationToken`. OTP challenges live in **`settings_verification_challenges`**; team notice emails fire after successful save. Each payment method may have an **optional** QR (`paymentMethods[].qrImageUrl`); upload stages Storage only until OTP-gated PATCH; canceling OTP or a failed verified save reverts the Payment draft. Guest form and ready-for-check-in email show QR only when uploaded. Account name uses full-name validation; **Save Changes** is disabled while dirty required payment fields fail validation. See [`docs/workflow/done/sensitive-settings-email-otp.md`](workflow/done/sensitive-settings-email-otp.md) and property/parking Settings route guides.

**Next-stay voucher reveal styles:** Property **Reviews & vouchers** Manage modal sets `app_settings.voucher_reveal_style` (`reel` \| `wheel` \| `flip`, default `reel`). Guest `/sd-form` and guest-review load it via `get-sd-form` / `get-guest-review` and animate in `VoucherReveal` after a server-authoritative `claim-sd-voucher` roll. Plan: [`docs/workflow/done/voucher-reveal-styles.md`](workflow/done/voucher-reveal-styles.md).

**Media upload optimization:** every image uploader (host + guest) routes the picked file through `prepareUpload` (`ui/src/lib/media/`) — a Web Worker downscale + re-encode (quality-first presets: gallery 3840px WebP, content 2048px WebP, avatar 512px, documents near-lossless pass-through) before the request body is built; `browser-image-compression` is lazy-`import()`-ed (CI-asserted out of the initial bundle). One unified size ceiling per kind (image 10 MB, avatar 5 MB, document/PDF 12 MB, video 50 MB) lives in `_shared/uploadLimits.ts` (`assertWithinUploadLimit`) + client mirror `ui/src/lib/media/uploadLimits.ts`, replacing ~7 hardcoded limits. Rollout controls: global kill switch `VITE_DISABLE_IMAGE_OPTIMIZATION=1`; per-surface staged rollout `VITE_IMAGE_OPT_SURFACES` (rollout groups `settings`→`galleries`→`marketing`→`guest-profile`→`guest-documents`) — **unset** ships every group live **except `guest-documents`**, which stays a ceiling-only pass-through until the OCR-regression gate runs. Full detail + preset table: [`docs/architecture/storage.md`](architecture/storage.md) §7.1; plan: [`docs/workflow/done/image-video-upload-optimization.md`](workflow/done/image-video-upload-optimization.md); manual QA + gates: [`docs/guides/testing/image-upload-optimization-manual.md`](guides/testing/image-upload-optimization-manual.md).

**Property team RBAC (granular):** Assignable property role is **`ADMIN`** only (org owner / org Admin / platform admin stay implicit). Access is a JSONB leaf-id catalog (~81 ids) with seeded templates **Full Access** / **Operations** / **Read Only**. Server catalog: `_shared/propertyTeamPermissions.ts` + templates; client mirror: `ui/.../team/lib/propertyTeamConstants.ts` + `propertyPermissionCatalog.ts`. Plan entitlements compose as an inner gate (permission = visibility, plan = actionability) via `requirePropertyPermissionAndFeature`. Marketing Studio uses `marketing.*` leaves (Phase 7). Parking still uses coarse `MANAGER`/`STAFF`/`VIEWER` until Phase 9. Shipped plan: [`docs/workflow/done/granular-team-permissions.md`](workflow/done/granular-team-permissions.md). Route guide: [`docs/guides/routes/org/property/team.md`](guides/routes/org/property/team.md).

**Marketing guest reviews → social content:** Hosts pick completed-stay reviews in Marketing Design or Video (**Reviews** category) via a **Reviews** list under Templates (`GET list-property-guest-reviews`, `marketing:view`) and seed Quiet Coast **Reviews** canvas presets or **Guest love** / **Stay again** reels. Source `guest_reviews` rows stay immutable; Airbnb external quotes are not social-seeded. Plan: [`docs/workflow/done/marketing-guest-review-studio.md`](workflow/done/marketing-guest-review-studio.md). Route guide: [`docs/guides/routes/org/property/marketing.md`](guides/routes/org/property/marketing.md).

**Superhost (earned org badge):** Org-wide trust badge — no Airbnb proof import. Four rolling-365-day criteria (rating, inbox response, cancellation rate, activity) assessed quarterly (Jan/Apr/Jul/Oct 1, Asia/Manila). Badge: `organizations.settings.superhost.earned`; public `isSuperhost` via `_shared/orgSuperhost.ts`. Host progress: **Org settings → Trust** (`get-org-superhost-progress`). Cron: `superhost-assessment-cron`; manual: `reassess-org-superhost`. Data: `inbox_thread_metrics`, `superhost_assessment_runs`. Plan: [`docs/workflow/for-testing/superhost-program.md`](workflow/for-testing/superhost-program.md).

## Host pricing tiers (catalog + entitlements)

**Org-level subscription catalog** (Free → Managed + a retired commission plan) — one `org_subscriptions` row per org, priced **per enrolled property** (tier's per-property rate × property count, volume-discounted) with no property-count cap. There is no per-property subscription: `resolvePropertyEntitlements(propertyId)` resolves entirely through the property's org, falling back to Free when a property isn't enrolled. Plans: [`host-plans-and-pricing-tiers.md`](workflow/done/host-plans-and-pricing-tiers.md) (original per-property foundation, historical), [`org-level-billing-migration.md`](workflow/done/org-level-billing-migration.md) (current model — source of truth), [`pricing-portfolio-bundling.md`](workflow/done/pricing-portfolio-bundling.md) (superseded flat-cap bundle add-on, historical). The feature-gating audit that swept every module against this catalog, hardened server-side enforcement, added the tier-badge system, redesigned the upgrade modal with proration, and added org-wide pooling for quantity-limited features: [`tier-feature-alignment-audit.md`](workflow/done/tier-feature-alignment-audit.md) — canonical feature × tier matrix + gate inventory in [`plans-feature-matrix.md`](architecture/plans-feature-matrix.md).

The host then forwards `<origin>/form?complete=<token>` (`issue-guest-form-completion-token` → `get-form-completion` → `submit-form-completion`) so the OTA guest fills in the rest against that row with the dates locked. Notifications `booking_external_imported` / `booking_guest_form_completed`. Plan: [`workflow/done/airbnb-calendar-sync.md`](workflow/done/airbnb-calendar-sync.md).
