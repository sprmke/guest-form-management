## 6. Data model (`guest_submissions`)

**`organizations`** / **`properties`** (migration **`20260629180000_multi_tenancy_foundation.sql`**; **`tower`** + **`unit_number`** + global unique pair in **`20260821140000_properties_tower_unit_columns.sql`**; **`properties.slug`** globally unique in **`20260821150000_properties_slug_globally_unique.sql`** — required because guest **`?property=`** resolves by slug alone): single-owner orgs (`owner_id` → `auth.users`), properties per org (`organization_id`), slug-based URLs. **`tower`** is one of `Monaco` \| `Bali` \| `Barbados`; **`unit_number`** is exactly four digits; **`tower_and_unit`** remains the display string (`Monaco 2604`). **Today:** duplicate tower+unit pairs are rejected on **`create-organization`**, **`create-property`**, and **`update-property`** regardless of status. **Planned ([#120](https://github.com/sprmke/kame-homes/issues/120)):** uniqueness only among **`ACTIVE`** properties so successive sublessees / hosts can reuse the same unit after prior listings are **`INACTIVE`**. Display **name** uniqueness is **per organization** (not a cross-host lock). **`guest_submissions`**, **`finance_line_items`**, **`maintenance_items`**, and singleton settings tables gain optional-then-required **`property_id`**; default backfill assigns **Kame Home** / **Monaco 2604**.

**`property_blocked_dates`** (migration **`20260801120000_property_blocked_dates.sql`**): owner-managed unavailable night ranges per property. Columns: `id`, `property_id`, `start_date`, `end_date`, optional `note`, `created_at`, and nullable `created_by`; `end_date > start_date` and ranges use checkout-exclusive **`[start_date, end_date)`** semantics. Admin writes use **`property-pricing`** with `pricing:edit`; partial unblocks call transactional RPC **`unblock_property_blocked_dates`** (migration **`20261001150000_unblock_property_dates_function.sql`**) so remaining range segments are preserved. Public **`get-booked-dates`** returns these ranges alongside bookings, and **`submit-form`** rejects blocked nights server-side.

**`parkings`** / **`parking_settings`** (migration **`20260918120000_parkings.sql`**): one row = one parking slot per org (`organization_id`). **`slug`** globally unique; physical slot uniqueness on **`(residence_name, tower, level, slot_label)`**. **`parking_type`**: `inside_tower` \| `outside_tower` \| `motorcycle`. **`accepted_vehicle_types`** (`TEXT[]`, `car` \| `motorcycle`, migration **`20261016120000_parking_accepted_vehicle_types.sql`**) drives broadcast candidate matching; car-size fit tiers (`compact`/`sedan`/`suv`/`van`) are derived via `resolveVehicleFit`, never stored. **`organizations.host_modes`** (`TEXT[]`, values `property` \| `parking`) tracks which asset types the org hosts. Standalone parking reservations: **`guest_submissions.parking_id`** (migration **`20260731120000_guest_submissions_parking_id.sql`**) — mutually exclusive with **`property_id`**; org **`list-bookings`** unions both. Guest-stay **`need_parking`** on property rows is unchanged.

**Parking broadcast** (migrations **`20261017120000_parking_booking_broadcast.sql`**, **`20261017130000_parking_broadcast_terminal_check_fix.sql`**, cron in **`20261018120000_parking_broadcast_expire_cron.sql`**): `guest_submissions_status_check` widened with **`PENDING_HOST_ACCEPTANCE`** / **`NO_HOST_AVAILABLE`**; a broadcast row has **`parking_id IS NULL`** until claimed, only legal when **`parking_request_organization_id IS NOT NULL`** and status is one of the two new statuses (or the terminal `CANCELLED`). New `guest_submissions` columns: **`parking_request_organization_id`**, **`requested_vehicle_type`**, **`parking_broadcast_expires_at`** (TTL deadline), **`parking_claimed_at`**, **`parking_endorsement_note`** (host-authored, shown to guest post-claim, ≤2000 chars). **`parking_booking_broadcasts`**: one row per candidate parking per broadcast round — `booking_id`, `parking_id`, `response` (`pending`\|`claimed`\|`declined`\|`expired`), `notified_at`, `responded_at`. First-Accept-wins is enforced by a guarded `UPDATE guest_submissions ... WHERE status = 'PENDING_HOST_ACCEPTANCE'`, not by the broadcast table — see **[[parking-workflow|Parking workflow]]** for the full status graph and race-safety rationale.

**Property team RBAC (migration **`20260908120000_property_team_rbac.sql`**):** **`property_custom_roles`** (UUID id, name, `permissions` JSONB per property), **`property_members`** (`user_id`, `role_id` = built-in literal or custom UUID, `permissions`, `status` active\|inactive, `saved_permissions`), **`property_invitations`** (email, token, 7-day expiry, status). Server contract: **`supabase/functions/_shared/propertyTeamPermissions.ts`**; access helper: **`orgAuth.ts#verifyPropertyAccess`**. Org owner has implicit full access without a member row.

Created in migrations; key points:

- **`id`**: UUID; client may supply on insert (form sends predetermined id).
- **Telegram marketing settings:** table **`telegram_marketing_settings`** (single row `id = 1`) holds templates, **`daily_reminder_times_manila`** (JSONB Manila clock slots synced to **`pg_cron`**), toggles — see **[[telegram-marketing-reminders|Telegram marketing reminders]]**.
- **Dates**: Stored as **TEXT** (`MM-DD-YYYY` in DB via `transformFormToSubmission`); API and overlap logic accept normalization between `MM-DD-YYYY` and `YYYY-MM-DD`.
- **Times**: Stored as human-readable strings (DB defaults `02:00 PM` / `11:00 AM` in original migration; UI uses 24h in schema defaults then displays).
- **`status`**: Added in `20250113000000_add_booking_status.sql` — values used in code: **`booked`** (active), **`canceled`**. Comments mention “booked \| canceled”; sheet uses **Booked** / **Canceled** labels.
- **Pets**: `pet_type` added in later migration; URLs for vaccination and pet image in storage.
- **Constraints**: Check constraints on email pattern, guest counts, parking conditional fields, pet conditional fields, date ordering, time regex (see migration).

**`finance_line_items`** (migration **`20260527120000_finance_line_items.sql`**, …, parking scope **`20260919120000_finance_line_items_parking_id.sql`**): property- or parking-scoped **expense** / **income** transaction lines — exactly one of **`property_id`** or **`parking_id`** per row (`kind`, **`label`** (required), **`amount`** (required, &gt; 0), **`category`** (required), `occurred_on` DATE, `notes`, optional `receipt_path`, `created_by`, optional **`recurrence_series_id`** + **`recurrence_interval`** … (`daily` \| `weekly` \| `monthly` \| `twice_monthly` \| `every_2_months` \| `quarterly` \| `every_6_months` \| `yearly`), optional Telegram reminder columns (**`telegram_reminder_enabled`**, **`telegram_due_date`**, **`telegram_days_before`**, **`telegram_reminder_interval`** `hourly` \| `every_2_hours` \| `every_4_hours` \| `every_12_hours` \| `daily_noon`, **`telegram_message_template`**), optional **`paid_at`** (stops reminders for every interval when set). Recurring creates are **materialized** — one row per occurrence through **`recurrence_until`**; **`telegram_due_date`** on each row is that occurrence's **`occurred_on`** (bulk series PATCH does not overwrite per-row due dates). **`telegram-finance-cron`** sends at most **one** reminder per **`recurrence_series_id`** per tick. PATCH/DELETE accept **`scope`**: `this` \| `this_and_future` \| `all` for series edits; PATCH with a new **`occurred_on`** shifts dates in scope (`all` = same day offset for every row; `this_and_future` = regenerate from the new date through the series end). PATCH body may include **`marked_paid`** (`true` sets **`paid_at`**, `false` clears it). RLS enabled with **no policies** — admin edge functions only (`finance-line-items`). Used by **`/finance`** **Transactions** tab and included in **`finance-summary`** `grandNet`.

**`maintenance_items`** (migration **`20260818120000_maintenance_module.sql`**, **`every_2_months`** interval **`20260819120000_recurrence_every_2_months.sql`**, **`twice_monthly`** **`20260724140000_recurrence_twice_monthly.sql`**, **`every_6_months`** **`20260724150000_recurrence_every_6_months.sql`**): property upkeep reminder lines — **`label`** (required), **`category`**, **`scheduled_on`** DATE, `notes`, optional **`recurrence_series_id`** + **`recurrence_interval`** (`daily` \| `weekly` \| `monthly` \| `twice_monthly` \| `every_2_months` \| `quarterly` \| `every_6_months` \| `yearly`), same Telegram reminder columns as finance, optional **`completed_at`** (stops reminders; UI **Mark as done**). Companion tables: **`telegram_maintenance_settings`**, **`maintenance_telegram_reminder_log`**. Hourly cron via **`sync_telegram_maintenance_hourly_cron_job`**. RLS enabled with **no policies** — admin edge functions only (`maintenance-items`). Used by **`/maintenance`**.

**`import_batches`** / **`import_batch_rows`** (migration **`20261007120000_import_batches.sql`**): CSV import wizard staging — one batch per upload, property-scoped (`organization_id`, **`property_id`** required). Batch **`status`**: `uploaded` → `mapping` → `mapped` → `previewing` → `previewed` → `committing` → `committed` \| `failed`; revert path → `reverting` → `reverted`. Stores **`column_headers`**, **`column_mapping`**, **`storage_path`**, **`row_count`**, timestamps. Row table: **`raw_data`** / **`mapped_data`** JSONB, **`validation_status`** (`valid` \| `error` \| `skipped`), **`validation_errors`**, optional **`committed_row_id`** → `guest_submissions.id`. RLS enabled with **no policies** — service role via `import-*` edge functions only. **`guest_submissions.imported_from_batch_id`** links committed bookings back to their batch. Migration **`20261007130000_add_imported_booking_status.sql`** adds **`IMPORTED`** to the `guest_submissions.status` CHECK constraint.

**`custom_pages`** (migration **`20261018130000_custom_pages.sql`**): per-property template selection for the **Public Pages** stay-guide template — `property_id`, `page_type` (CHECK'd, v1: `stay_guide` only), `template_key`, unique on `(property_id, page_type)`. Host paths lazy-create; guest DTOs (`get-guest-stay-guide`, `get-public-property`) include `sectionConfig` via read-only defaults when missing. Separate from `custom_pages.template_key` and `property_template_contents`. Shipped: **[[workflow/done/page-editor-public-pages]]**.

**`pricing_plans`** / **`property_subscriptions`** / **`property_subscription_events`** / **`booking_commission_charges`** (migration **`20261023120000_pricing_plans_foundation.sql`**): host tier catalog + one live subscription per property + audit + commission ledger at **`COMPLETED`** (commission plan **retired from live UI** 2026-08-24 — inactive catalog row; see plans-feature-matrix pending section). **`pricing_plans.discount_percent`** (0–100, migration **`20261031140000_pricing_plan_discounts.sql`**) — per-tier list discount; host/checkout price = **`floor(price_php × (100 − discount_percent) / 100)`** (whole pesos). **PayMongo billing** (migration **`20261024120000_property_paymongo_billing.sql`**): **`property_payment_transactions`** (checkout ledger), **`platform_payment_settings`** (singleton PayMongo rails + dunning config), **`processed_paymongo_events`** (webhook dedupe); **`property_subscriptions.grace_period_ends_at`**, **`cancel_at_period_end`**. **`assignPropertyToPlan`** snapshots discounted checkout price and syncs AI credits; paid checkout via **`create-subscription-checkout`** + **`paymongo-webhook`** fulfillment.

**`notifications`** / **`notification_reads`** (migration **`20261015120000_notifications.sql`**): in-app Notification Center. **`notifications`** is the broadcast event (`organization_id` required, optional `property_id`/`parking_id`, **`type`** CHECK'd to 7 literals — `booking_pending_review`, `booking_ready_for_checkin`, `booking_ready_for_checkout`, `booking_sd_refund_due`, `booking_gaf_auto_approved`, `booking_pet_auto_approved`, `inbox_new_message` — `title`, `body`, optional `booking_id` → `guest_submissions.id` / `conversation_id` → `social_conversations.id`, `metadata` JSONB, optional **`dedupe_key`**); **`notification_reads`** is per-admin read tracking (`notification_id`, `user_id`, `read_at`, unique pair) — **absence of a row means unread**, not a shared `read_at` column, so one admin dismissing a notification doesn't mark it read for the whole org. Partial unique index **`(type, dedupe_key) WHERE dedupe_key IS NOT NULL`** guards retried transitions/webhook redeliveries; **`_shared/notificationService.ts#createNotification`** does a plain insert and swallows `23505` rather than `ON CONFLICT`, since PostgREST can't target a partial index's predicate. RLS SELECT via **`user_can_access_org_notifications`** (org owner or active **`organization_members`** row — same gap as the social-inbox precedent: property/parking-only team members without an org row get no realtime push, a known v1 limitation). Edge functions (**`notifications-list`**, **`notifications-mark-read`**) run as service role behind their own **`org:dashboard:view`** / **`bookings:view`** gate, so they aren't limited by that RLS gap. `REPLICA IDENTITY FULL` + `supabase_realtime` publication power the org-scoped **`notifications-{orgId}`** realtime channel. Emission points: **`workflowOrchestrator.ts#transition()`** (the 3 booking-status types), **`approval-email-webhook`** (auto-approval types, live inbound path only), **`submit-form`** + **`databaseService.ts#createParkingBooking`** (`booking_pending_review`), **`metaInboxWebhookHandler.ts`** + **`webGuestChatService.ts`** (`inbox_new_message`) — see **[[booking-workflow|Booking workflow]]** for the side-effect matrix.

**`ai_dashboard_assistant_messages.attachments`** (migration **`20261019120000_ai_assistant_attachments.sql`**): JSONB `[{ name, mimeType, size, path }]` on user turns. Bytes live in private Storage **`ai-assistant-attachments`**, not in this column. Gemini sees `inlineData` for that turn only.

**Guest Inbox / social messaging** (migration **`20260910120000_social_inbox.sql`**, Meta hardening **`20261101120000_meta_inbox_webhook_health.sql`**, **`20261101121000_social_messages_human_agent_tag.sql`**, parking quick-reply/automation scoping **`20261103120000_inbox_parking_scope.sql`**): **`social_channel_connections`** (org/property/parking-scoped Meta Page rows + web channel metadata; **parking has no Meta UI** — Channels/Facebook/Instagram are property-only), **`social_conversations`**, **`social_messages`**, **`social_inbox_settings`**, **`social_reply_templates`**, **`social_webhook_events`**, **`meta_inbox_oauth_state`**. **`social_reply_templates`** and **`social_inbox_settings`** each carry a nullable **`parking_id`**: `NULL` = org-wide row used by property; set = a row scoped to that one parking (separate quick replies/automation from property, seeded from **`_shared/inboxDefaultQuickReplies.ts#INBOX_DEFAULT_PARKING_QUICK_REPLIES`**). **`social_inbox_settings`** has no single-column primary key anymore — one partial-unique row per `organization_id` where `parking_id IS NULL`, and one per `(organization_id, parking_id)` where it isn't; every direct query must filter on `parking_id` accordingly. Meta connection rows track webhook + token health: **`webhook_subscribed_at`**, **`webhook_last_verified_at`** (last successful `{pageId}/subscribed_apps` check), **`webhook_verify_attempts`** (increments on failed verify/resubscribe; UI **Fix connection** after ≥3), **`token_expires_at`** (populated from Graph **`/debug_token`** during webhook reconcile), **`error_message`** (webhook/permission/token warnings), **`status`** (`connected` \| `disconnected` \| `error`). **Disconnect** removes the connection and deletes synced Meta conversations for that scope. Outbound **`social_messages.message_tag`** is nullable; when set, only **`human_agent`** is allowed — records explicit **`HUMAN_AGENT`** tagged Meta DMs (24h–7d operator follow-ups). Route guides: **[[guides/routes/org/property/inbox]]**, **[[guides/routes/org/parking/inbox]]**; edge inventory: **[[edge-functions]]**; scheduled webhook healthcheck: **[[../archive/operations/scheduled-jobs-and-testing]]**.
